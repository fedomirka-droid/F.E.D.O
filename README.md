# F.E.D.O — локальный ИИ-ассистент

**F.E.D.O — Functional Event Detection Operator.**

Локальный ИИ-ассистент на Python для персонального компьютера:
нейросеть работает через LM Studio **на самой машине**, все данные
(профиль, чаты, память) хранятся локально и никуда не отправляются.
Windows + Linux.

Текущая версия: **v1.5.10**

---

## Что умеет F.E.D.O (линия v1.5)

### Чат
- диалог с локальной нейросетью (LM Studio, модель определяется
  автоматически через `/v1/models`);
- **много-чат с папками** (вкладка «Чаты»): новый чат, папки
  («Общий», «Проекты», свои), открыть/удалить;
- каждый чат — свой текстовый файл и **своя LLM-память**:
  чаты не путают контексты друг с другом;
- архив чата (`data/chats/<папка>/<чат>.txt`) — при старте последний
  чат восстанавливается в окно;
- память LLM между запусками (последние 10 сообщений на чат);
- имя пользователя задаёт **сам пользователь**: диалог при первом
  запуске + команды «меня зовут …» / «зови меня …».

### Личности
- режимы: **СССР**, **Джарвис**, **Современный**;
- **Агрессивный** (только standard-сборка, за подтверждением 18+):
  «ядовитый наставник» — унижение словами, мат как редкий акцент;
- **GOV-сборка** (`FEDO_BUILD = "gov"`, ветка `v1.5-gov-release`):
  без «Агрессивного», мат запрещён в prompt'е + фильтр на выходе LLM,
  заголовок помечен «(ГОС)».

### Голос
- TTS: русский (Silero v4_ru) + английский (Silero v3_en),
  язык определяется автоматически по письменности;
- мастерская голосов: выбор на слух (кнопка «Прослушать»);
- смешанная озвучка: RU+EN текст — одна запись, два голоса;
- голос пропускает блоки кода;
- микрофон (STT).

### Система
- монитор: CPU, RAM, диск, GPU/VRAM, температура, топ процессов;
- «Покажи состояние системы» / «Почему компьютер тормозит?» —
  отвечаются и **без** нейросети (прямой ответ монитора);
- действия с ПК (кроссплатформенно);
- Developer Mode: терминал (с блокировкой опасных команд),
  логи, отладка.

## F.E.D.O. Ecosystem — Personal Edition (v2.0)

Поверх Core построена персональная экосистема из четырёх компонентов.
Core при этом **не изменён**: его монитор, личности, prompt-ы и команды
переиспользуются через `ecosystem/backend/services/core_bridge.py`.

| Компонент | Что это | Где код |
|-----------|---------|---------|
| **Desktop** | Tauri 2 + React: чат, задачи, календарь, расписание, устройства, монитор, настройки; локальный backend как sidecar | `desktop/`, `ecosystem/backend/` |
| **HUB** | FastAPI + SQLite: авторизация, устройства, синхронизация, API для бота | `ecosystem/backend/` (role=hub) |
| **Mini** | Telegram-бот Aiogram 3 без собственной БД задач | `ecosystem/mini/` |
| **GPU Core** | Agent + AI-шлюз на домашнем ПК с RTX 3080 | `ecosystem/agent/` |

Ключевые возможности:

* AI Router 2.0 — режимы `local_only / hybrid / cloud_preferred / manual`,
  жёсткий запрет облака, отдельное разрешение на передачу истории, лимиты,
  отмена, стриминг, учёт расходов;
* offline-first синхронизация: UUID, версии, tombstones, outbox, идемпотентные
  операции, backoff, разрешение конфликтов без потери данных;
* импорт расписания ИС-21 из XLS/XLSX (merged cells, соседние группы, даты);
* Device Manager с белым списком команд, подписью канала HMAC и подтверждением
  опасных действий; Wake-on-LAN;
* безопасность: scrypt-пароли, opaque-сессии, отдельные токены устройств,
  шифрование API-ключей, rate limit, аудит.

### Быстрый старт (локально)

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements-ecosystem.txt

# 1) локальный backend Desktop (миграции применятся автоматически)
FEDO_ROLE=desktop python -m ecosystem.backend --role desktop --port 8765

# 2) интерфейс
cd desktop && npm install && npm run dev     # http://localhost:5173
```

Дальше: `docs/ECOSYSTEM.md`, `docs/DESKTOP_BUILD.md`, `docs/DEPLOY.md`,
`docs/MINI_INTEGRATION.md`, `docs/ECOSYSTEM_STATUS.md`.

Тесты экосистемы (без сети и без реального железа):

```bash
pip install -r requirements-dev.txt
pytest -q
```

## Архитектура

```
                ┌──────────────┐      ┌──────────────┐
                │     GUI      │      │   Console    │
                │ (CustomTk)   │      │ (--console)  │
                └─────────────┘      ──────┬───────┘
                       └──────────┬───────────┘
                                  ↓
                          ┌──────────────┐
                          │  AI Router   │
                          └──────────────┘
            ┌────────────────────┼────────────────────┐
            ↓                    ↓                    ↓
      LM Studio            Memory / Profile      System Monitor
      (auto model)      user_profile.json      CPU / RAM / GPU /
                      + чаты (папки)             Disk / Temps / Procs
                      chat_history/
```

- **AI Router** (`core/ai_router.py`) — единая точка входа:
  команды → системный запрос → LLM. Через роутер идут и GUI, и консоль.
- **Chat Manager** (`core/chat_manager.py`) — много-чат: реестр,
  папки, файлы чатов, LLM-память на чат.
- **Sanitizer** (`core/sanitizer.py`) — фильтр нецензурной лексики
  на выходе LLM (только GOV-сборка).

## Запуск

```bash
# GUI
python main.py

# Консоль
python main.py --console
```

Требования: Python 3.11, LM Studio с включённым локальным сервером
(`http://127.0.0.1:1234`), зависимости из `requirements.txt`,
для Linux — `libportaudio2` (звук).

Системные вопросы работают и без LLM:

```

  ...
```

## Версии и ветки

| Ветка | Что это |
|-------|---------|
| `v1.0-release` … `v1.5-release` | замороженные релизные линии |
| `v1.5-gov-release` | **GOV-сборка**: без «Агрессивного», без мата (для колледжа/госучреждений) |
| `arena/…` | рабочая ветка (активная разработка) |

История версий: v1.0 (прототип) → v1.3 (интерфейс) → v1.4 (ядро + голос)
→ v1.5 (память, характер, чаты) → v1.5.10 (GOV-сборка).
Подробности — в `CHANGELOG.md`.
