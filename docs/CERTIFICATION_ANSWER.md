# Задание: «Какую схему сертификации выбрать для моего проекта?»
## Тема: локальный ИИ-ассистент «F.E.D.O.»

### 1. Описание проекта
«F.E.D.O.» — локальный ИИ-ассистент для ПК (Windows/Linux). GUI-приложение + консольный режим: диалог с локальной нейросетью (LM Studio), голос (TTS RU/EN, микрофон), профиль пользователя и память, много-чат с папками, мониторинг системы (CPU, RAM, GPU, процессы). Для частников и учебных заведений. Функции, связанные с безопасностью: изоляция персональных данных (профиль, чаты, память хранятся только на локальном диске, запросы к LLM — только на localhost-сервер), ведение журналов событий и архивов чатов, защита функции «Агрессивный режим» подтверждением 18+, блокировка опасных команд в developer-терминале. Шифрование не реализовано (запланировано в v2.0).

### 2. Целевые рынки и заказчики
Сейчас: частные пользователи и учебные заведения РФ. Рост: коммерческие компании (локальный ИИ без отправки данных в облако). Перспектива: госсектор РФ (локальный ИИ на государственных машинах). Международный рынок пока не планируется. Требования заказчиков: бизнес — 152-ФЗ и ISO/IEC 27001; госсектор — сертификация ФСТЭК.

### 3. Необходимые схемы сертификации
- Для частников/образования (сейчас): обязательной НЕТ. Желательна: декларация соответствия (152-ФЗ) + внутренняя политика ИБ.
- Для коммерческих компаний: обязательно соответствие 152-ФЗ; желательно ISO/IEC 27001 у разработчика (тот же «пакет доверия», что у облачных платформ — в справочнике Azure: ISO 27001/27017/27018).
- Для госсектора (перспектива): обязательна сертификация ФСТЭК (Приказ №21) — система работает с персональными данными; класс по обработке ПДн (1С–2С) (аналогия из справочника: PostgreSQL Pro — класс 2К, «Kaspersky Security for Internet Gateway» — класс 2К).
- При добавлении шифрования (v2.0): обязательна сертификация ФСБ — только для криптомодуля, через интеграцию сертифицированного СКЗИ (аналогия: «Крипто ПРО CSP» — ФСБ + FIPS 140-2).
- Для ЕС (резерв): желательна Common Criteria (EAL2+) — международное признание (в справочнике EAL4+ — уровень ОС и межсетевых экранов: Astra Linux, Windows 10).

### 4. Обоснование выбора
Главное свойство продукта — данные не покидают машину (локальная нейросеть, локальное хранилище). Это напрямую отвечает требованию 152-ФЗ о локализации данных и упрощает соответствие ФСТЭК: модель угроз меньше, т.к. нет канала передачи данных наружу. ФСТЭК выбран, потому что система обрабатывает ПДн (профиль, чаты) и целится в госсектор. ФСБ — условно: только при добавлении шифрования, и не «своей» крипто, а через сертифицированное СКЗИ. Common Criteria отложен: EAL4+ — уровень ОС (дорого и долго), для приложения реалистичен EAL2+, но на текущем этапе стоимость несоразмерна.

### 5. Возможные сложности и риски
- ФСТЭК: 4–6 месяцев, от сотен тыс. ₽, нужен аккредитованный орган. Решение: не начинать «на всякий случай» — только под конкретный госконтракт; до этого — декларация соответствия.
- Common Criteria: от ~30 000 €, 1–2 года. Решение: отложить; сначала собственный анализ угроз и публичный аудит кода (дешевле и быстрее).
- Нет категории «ИИ-ассистент» в стандартах ФСТЭК. Решение: позиционировать как «ПО для обработки персональных данных» — стандартная категория Приказа №21.
- Локализация: ФСТЭК/ФСБ требуют российского заявителя. Решение: сейчас разработчик — физлицо (студент), юрлицо — при старте коммерческих продаж.
- Дефицит ЦСИ для нишевых продуктов. Решение: отбирать орган при готовности контракта, заранее готовить комплект документов (технический паспорт, модель угроз).

**Вывод:** сейчас — декларация соответствия + политика 152-ФЗ; целевая обязательная схема — ФСТЭК (Приказ №21); при шифровании — ФСБ для криптомодуля; на международный рынок — CC (EAL2+).
