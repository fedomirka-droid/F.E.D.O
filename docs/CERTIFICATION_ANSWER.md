# Задание: «Какую схему сертификации выбрать для моего проекта?»
## Мой проект: локальный ИИ-ассистент «F.E.D.O.»

### 1. Описание проекта
F.E.D.O. — программа-ассистент, которая живёт на компьютере пользователя. Работает на Windows и Linux, есть окно (GUI) и консольный режим. Говорит с пользователем через нейросеть, но нейросеть крутится локально на ПК (через LM Studio), а не в облаке. Умеет говорить голосом (русский и английский), запоминать пользователя (имя, город, предпочтения), вести чаты с папками, смотреть состояние компьютера (CPU, RAM, GPU, процессы).

Сделано для личного использования и учебных заведений — для тех, кому нужен ассистент, который не шлёт данные никуда.

Функции, связанные с безопасностью:
- все данные (профиль, чаты, память) лежат только в локальной папке на ПК;
- запросы к нейросети уходят только на локальный сервер (localhost), в интернет ничего не отправляется;
- ведётся журнал событий, каждый чат архивируется в текстовый файл;
- «агрессивный» режим за подтверждением 18+ (а в отдельной гос-версии этого режима вообще нет + фильтр мата на выходе);
- в developer-терминале блокируются опасные команды (rm -rf, reboot и т.д.);
- шифрования данных пока нет — это планируется.

### 2. Целевые рынки
- Сейчас: частники и учебные заведения РФ (базовая аудитория).
- Дальше: компании, которым нужен локальный ИИ, чтобы не слать данные в облако.
- Перспектива: госсектор — локальный ассистент на государственных ПК.
- Международный рынок пока не планируется.

Требования заказчиков: бизнес — 152-ФЗ и желательно ISO/IEC 27001 у разработчика; госсектор — сертификация ФСТЭК.

### 3. Схемы сертификации
- Частники/образование (сейчас): обязательной сертификации нет. Желательно: декларация соответствия (152-ФЗ, т.к. программа хранит персональные данные) + внутренний документ «как мы защищаем данные» (политика ИБ).
- Компании: 152-ФЗ всё равно обязателен; ISO/IEC 27001 у разработчика — плюс. Это тот же «пакет доверия», что у облачных платформ (в справочнике: Azure — ISO 27001/27017/27018).
- Госсектор (перспектива): обязательна сертификация ФСТЭК (Приказ №21) — система работает с персональными данными. По аналогии из справочника: PostgreSQL Pro — класс 2К, «Kaspersky Security for Internet Gateway» — класс 2К. Наша система проще (нет функций СЗИ), поэтому класс — по обработке персональных данных (примерно 1С–2С).
- Если добавим шифрование (запланировано): нужна сертификация ФСБ, но только для модуля шифрования. И делать это разумно не своей криптой, а подключив готовое сертифицированное (например, «Крипто ПРО CSP» — в справочнике у него и ФСБ, и FIPS 140-2).
- Европа (дальний план): желательна Common Criteria. В справочнике EAL4+ — это уровень операционных систем и межсетевых экранов (Astra, Windows); для программы нашего масштаба реалистично EAL2–3.

### 4. Почему такой выбор
Главное в нашем продукте: данные не покидают компьютер. Нейросеть локальная, все файлы локальные, сервер — localhost. Это главный security-аргумент:
- по 152-ФЗ это уже локализация данных — они физически никуда не уезжают;
- по ФСТЭК модель угроз проще — нет канала утечки в интернет;
- «on-premise» сам по себе аргумент для клиентов, которые не могут слать данные наружу.

Поэтому логика такая: сейчас — декларация соответствия (дёшево и быстро), ФСТЭК — когда появится госзаказ (тогда это уже обязательное), ФСБ — при добавлении шифрования через готовый сертифицированный модуль, Common Criteria — когда решим идти в Европу.

### 5. Сложности и риски
- ФСТЭК занимает 4–6 месяцев и стоит от сотен тысяч рублей, нужен аккредитованный орган. Как обойти: не делать «на всякий случай» — только под конкретный госконтракт, до этого хватит декларации.
- Common Criteria — дорого (от ~30 000 €) и долго (1–2 года). Как обойти: пока не делать; вместо этого собственный анализ угроз + публичный аудит кода — дешевле и понятнее заказчику.
- В стандартах ФСТЭК нет категории «ИИ-ассистент». Как обойти: заявлять продукт как «ПО для обработки персональных данных» — это стандартная категория Приказа №21.
- ФСТЭК/ФСБ требуют российского заявителя (юрлицо). Как обойти: сейчас разработчик — физлицо (студент), юрлицо — при старте продаж.
- Не каждая сертификационная лаборатория (ЦСИ) возьмётся за мелкий продукт. Как обойти: выбирать лабораторию уже под контракт, а документы (технический паспорт, модель угроз) готовить заранее.

**Вывод.** На текущем этапе — декларация соответствия (152-ФЗ) + внутренняя политика ИБ. При появлении госзаказа — ФСТЭК (Приказ №21). При добавлении шифрования — ФСБ только для криптомодуля (через готовое сертифицированное СКЗИ). Для выхода в Европу — Common Criteria (от EAL2+).
