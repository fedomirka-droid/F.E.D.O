# F.E.D.O. Mini — интеграция Telegram

## Принцип

Бот не создаёт конкурирующую базу задач. Он — тонкий клиент HUB:

```
Telegram → ecosystem/mini/bot.py → ecosystem/mini/hub_client.py
        → HUB /api/bot/* (X-Bot-Token) → задачи/расписание/устройства
```

Если у тебя уже есть проект **F.E.D.O. Mini 2.1** (Aiogram 3), его бизнес-логику
можно направить на тот же адаптер: скопируй `hub_client.py`, `formatting.py`,
`keyboards.py` и замени свои вызовы БД на вызовы `HubClient`.

## Что реализовано

Команды: `/start`, `/today`, `/tasks`, `/schedule`, `/devices`, `/ai`, `/status`,
`/link КОД`, `/help`.

Кнопки: Сегодня · Завтра · Задачи · Расписание · Добавить задачу · Статус ПК ·
Спросить AI · Статус, а также действия по задаче: Начать, Завершить, +15 минут,
Пропустить, Вернуть в работу, и устройства: статус, сон (с подтверждением).

Свободный текст уходит в AI (те же настройки приватности, что в Desktop).

## Привязка аккаунта

1. Desktop → Настройки → Telegram → «Создать код».
2. Бот: `/link КОД`.
3. HUB: `POST /api/bot/link` (сервисный токен) → `TelegramAccount(owner_id, telegram_id)`.

Свойства кода:

* 8 символов из алфавита без похожих букв, TTL 10 минут;
* хранится только SHA-256 хэш, в логи/аудит не пишется;
* одноразовый, лимит попыток погашения, rate limit по `telegram_id`;
* Telegram ID сам по себе доступа не даёт: без записи `TelegramAccount`
  все `/api/bot/*` отвечают 403.

## Права

* Бот аутентифицируется **сервисным** токеном — у него нет сессии владельца.
* Каждый запрос содержит `telegram_id`; HUB сам определяет владельца.
* Чужие устройства недоступны (404), опасные команды требуют подтверждения в Desktop.

## Запуск

```bash
export FEDO_TELEGRAM_BOT_TOKEN=123:ABC
export FEDO_HUB_URL=https://fedo.example.com
export FEDO_BOT_SERVICE_TOKEN=<тот же, что на HUB>
python -m ecosystem.mini
```

Напоминания: бот опрашивает `/api/bot/reminders` раз в минуту и отправляет
сообщения без дублей (ключ: telegram_id + задача + время).

## Если исходники Mini недоступны

Реализован полностью тестируемый адаптер и контракты API
(`tests/test_telegram.py`, `tests/test_mini_bot.py`). Для подключения реального
Mini 2.1 достаточно заменить слой доступа к данным на `HubClient` — схема
эндпоинтов зафиксирована в `ecosystem/backend/routers/telegram.py`.
