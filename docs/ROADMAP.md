# F.E.D.O. — Roadmap: от проекта в колледже к продукту

План развития F.E.D.O. по стадиям: что уже есть, что делать
для защиты, что превращает проект в продукт и как выходить на рынки.

---

## Стадия 0 — Фундамент (текущее состояние)

Готово ✅:

- полная история версий: v1.0 → v1.5.9, пять веток `vN.x-release`
  и рабочая ветка (видно, как проект развивался — это аргумент
  на защите: не «всё за вечер», а управляемая разработка);
- CHANGELOG по каждой версии (60% фиксы / 40% фичи);
- архитектура: GUI + Console → **AI Router** → System / LLM,
  голос (TTS RU/EN), память, много-чат с папками;
- GitHub-репозиторий (публичный), git-процессы (ветки, теги).

Сделать 🔄:

- `docs/` — архитектура (диаграмма), потоки данных, этот roadmap
  и `SECURITY.md` (уже есть);
- описание проекта на 2–3 страницы (проблема → решение →
  архитектура → безопасность → планы);
- демо-видео на 3 минуты (чаты, голос, мониторинг, агрессивный
  режим, консольный режим).

## Стадия 1 — Защита в колледже

Состав презентации:

1. Проблема: облачные ИИ шлют данные наружу, нет персонального
   ассистента «у себя на ПК».
2. Решение: F.E.D.O. — локальный ИИ-ассистент (схема архитектуры).
3. История версий v1.0 → v1.5.9 (таймлайн — видно, что проект
   живёт и развивается).
4. Фичи + живое демо (5–7 минут).
5. **Безопасность**: локальность данных, 152-ФЗ, выбор схемы
   сертификации (из `docs/SECURITY.md`) — это и есть ответ
   на задание «какую схему сертификации выбрать».
6. Планы: v1.6+ (см. ниже).

Аргументы, которые работают у комиссии:

- «Данные не покидают устройство» — безопасность по архитектуре;
- кроссплатформенность (Windows + Linux);
- управляемый процесс (ветки, релизы, changelog).

## Стадия 2 — Продуктизация (v1.6 – v1.9)

- **v1.6** — «Гибридный интеллект»:
  1) Semantic Router (понимание типа запроса),
  2) Gemini Hybrid (сложные запросы → облако, с индикацией 🟢/🟠
     и отключением), 3) Push-to-Talk STT (локальный Silero).
- **v1.7** — Telegram-интерфейс (ассистент в мессенджере).
- **v1.8** — упаковка: один-клик установка (MSI/AppImage),
  автонастройка LM Studio, первый запуск без знаний git.
- **v1.9** — hardening: шифрование хранилища `data/`,
  локальный ключ доступа к API, резервные копии.

После v1.9 F.E.D.O. — уже не «скрипт с GUI», а продукт
с установщиком, документацией и ИБ-политикой.

## Стадия 3 — Выше (v2.0+)

- **v2.0** — «всегда включён»: JARVIS-режим (wake word,
  постоянное прослушивание), дистрибутив (F.E.D.O. OS на
  базе Linux-образа), голосовой интерфейс полностью.
- **Выход на рынки:**
  1) частники/университеты (база, сертификация не требуется);
  2) B2B: ISO/IEC 27001 у разработчика (когда появится команда
     и первый контракт);
  3) госсектор: ФСТЭК (Приказ №21) под конкретный заказ;
  4) международный: Common Criteria (от EAL2+) — «длинная игра».
- **Открытость:** GitHub, сообщество, гранты и конкурсы
  (учебные программы ускорения, хакатоны, «Студент-стартап») —
  публичная история версий уже сейчас это позволяет.

---

## Ключевой принцип

Не перескакивать стадии: сначала защита (стадия 1) на том,
что уже есть, параллельно v1.6 (стадия 2), сертификация —
только когда появляется конкретный заказчик (стадия 3).
60% фиксы / 40% фичи — правило каждого релиза.
