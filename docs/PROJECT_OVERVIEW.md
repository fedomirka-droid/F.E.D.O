# F.E.D.O. — всё о проекте

Полный обзор: что это, как развивалось, как устроено, где что лежит,
какие есть долги и что дальше. Документ-справка — можно показывать
комиссии, партнёру или другому ИИ.

---

## 1. Что это

**F.E.D.O. (Functional Event Detection Operator)** — локальный ИИ-ассистент
для персонального компьютера. Нейросеть работает **на самой машине**
через LM Studio (OpenAI-совместимый API на localhost), все данные
хранятся локально. GUI (CustomTkinter) + консольный режим.
Windows + Linux.

Ключевая идея: **данные не покидают устройство** — в отличие от облачных
ассистентов, F.E.D.O. физически не шлёт запросы и личные данные наружу.

- Автор: **fedomirka** (F.E.D.O. — корень фамилии)
- Репозиторий: `github.com/fedomirka-droid/F.E.D.O` (public)
- ТГ-канал «F.E.D.O» — анонсы версий (стиль: без эмодзи, «—» списки,
  в конце «Следующий этап: …»)
- Родственный бренд: музыкальный лейбл **fds1.ru** («FDS1 Universe»)
- Текущая версия: **v1.5.10**

## 3. Архитектура

```
┌──────────────┐   ┌──────────────┐
│  GUI (CTk)   │   │   Console    │
└──────┬───────┘   └──────┬───────┘
       └─────────┬─────────┘
                 ↓
          ┌─────────────┐
          │  AI Router  │  core/ai_router.py
          └─────────────┘
     ┌──────────┼──────────┐
     ↓          ↓          ↓
 Команды    System        LLM
 (локальные) (монитор,    (LM Studio,
  «система»,  офлайн-      модель auto
  «покажи»…)  ответы)      через /v1/models)
```

- **AI Router** — единая точка входа, GUI и консоль ходят через него.
- **Chat Manager** (`core/chat_manager.py`) — реестр чатов и папок
  (`data/chats/chats.json`), файлы чатов, LLM-память на чат.
- **LLM client** (`ai/llm_client.py`) — LM Studio: авто-модель, контекст
  (профиль + память + снимок системы), сложность → max_tokens,
  температура 0.9 (Агрессивный) / 0.6 (остальное), память 10 сообщений
  на чат.
- **Sanitizer** (`core/sanitizer.py`) — фильтр нецензурной лексики
  (RU/EN, полные формы, без ложных срабатываний) — только GOV-сборка.

### Модули

```
ai/          llm_client.py, prompts.py (личности, языковые правила)
core/        ai_router, assistant (консоль), chat_manager, commands,
             complexity, logger, memory, pc_commands, proxy_guard,
             sanitizer, settings, settings_manager, system_monitor,
             user_profile
interface/   gui.py (CustomTkinter), console_ui.py
voice/       tts.py (Silero v4_ru + v3_en), stt.py (SpeechRecognition)
docs/        ROADMAP.md, SECURITY.md, CERTIFICATION_ANSWER.md,
             PROJECT_OVERVIEW.md (этот файл)
```

## 4. Технологии

- **Python 3.11**, CustomTkinter 6.0.0, requests, psutil, GPUtil,
  colorama, certifi, torch + sounddevice (Silero), SpeechRecognition
- **LLM:** LM Studio (локальный OpenAI-совместимый сервер,
  `http://127.0.0.1:1234`), модель определяется через `/v1/models`
- **TTS:** Silero — RU v4_ru (aidar/eugene/baya/kseniya/xenia),
  EN v3_en (en_0…en_117); смешанная озвучка одной записью;
  код не озвучивается
- **STT:** SpeechRecognition (Google) — **старое решение, в планах
  замена на локальный Silero STT** (v1.6.2, push-to-talk)

## 5. Железо и модели

| Машина | Железо | Модель | Примечания |
|--------|--------|--------|------------|
| ПК (Windows, юзер `miraf`) | RTX 3080 8GB + 24GB RAM | **Qwen2.5 7B Instruct Q4_K_M** (~4.7GB) | 25–40 tok/s; здесь «ядовитый наставник» работает по-настоящему; GGUF качался напрямую с HF (~9 МБ/с) |
| Ноутбук (Linux, хост `f-e-d-o-os`) | 16GB RAM, iGPU (500MB VRAM) | **Qwen2.5 3B Instruct Q4_K_M** (~2GB) | ~8–15 tok/s на CPU; загружена VL-версия (лучше обычная 3B); 3B «держит» агрессивный prompt слабо — ответы вежливые, это предел модели, а не баг F.E.D.O. |

Silero-кэш на Linux: `~/.cache/torch/hub/snakers4_silero-models_master`,
голоса — в `src/silero/model/` (v4_ru.pt, v3_en.pt). Офлайн-установка
через браузер (в терминале ноута проблемы с DNS).

## 6. Где что хранится (data/)

| Файл/папка | Что |
|------------|-----|
| `data/settings.json` | настройки: режим личности, ответ (short/normal/detailed), язык, голос (RU/EN), developer_mode, aggressive_unlocked, пороги сложности, LM URL, Gemini key |
| `data/user_profile.json` | профиль: имя, город, о пользователе, предпочтения, контекст, привычки |
| `data/memory.json` | общая память (ключ = значение) |
| `data/chats/chats.json` | реестр чатов и папок |
| `data/chats/<папка>/<чат>.txt` | архив чата (`[HH:MM:SS] отправитель: текст`) |
| `data/chat_history/<id>.json` | LLM-память **на каждый чат** (последние 10) |
| `data/logs/` | журнал сессии |

## 7. Характер (личности)

- **СССР** — советский инженерный оператор, «товарищ», ретрофутуризм,
  без мата
- **Джарвис** — «сэр», уверенный премиальный ассистент
- **Современный** — дружелюбный техконсультант
- **Агрессивный (18+, только standard-сборка)** — «ядовитый наставник»
  (v1.5.6): уничтожает словами; мат — редкий акцент «как у рабочего
  после смены» (~10%), главное — сарказм, обесценивание, холодное
  презрение; «Принято.» запрещено; извиняться не умеет;
  **пол (не нарушается):** нет угроз реальной безопасности/суицида,
  нет унижения по личным атрибутам, под тоном — технический ответ
- **GOV-сборка** — Агрессивного нет в принципе + жёсткие правила
  «мат запрещён безусловно» + фильтр на выходе

Интересные детали: при выключении говорит «Завершение сессии
оператора. Гашу контуры.», пустое имя пользователя → «товарищ».

## 8. Безопасность

- **Локальность данных** — главный security-аргумент: LLM локальная,
  файлы локальные, API — localhost
- Журнал событий + архивы чатов (аудит)
- 18+ гейт на Агрессивный режим (персистентный)
- Блокировка опасных команд в Developer Terminal
  (`rm -rf /`, `mkfs`, `dd if=`, `reboot`, `del /f`, `rmdir /s` …)
- proxy_guard: чистит proxy-переменные, добавляет localhost в исключения
- SSL через certifi
- Sanitizer (GOV) — мат на выходе невозможен
- **Сертификационный план** (docs/SECURITY.md): сейчас — декларация
  соответствия (152-ФЗ) + политика ИБ → госсектор — ФСТЭК (Приказ №21,
  класс ПДн) → при шифровании — ФСБ (через готовое СКЗИ, напр. Крипто
  ПРО CSP) → Европа — Common Criteria (EAL2+)

## 9. Как разрабатывается (процесс)

- Разработчик пишет требования и тестирует на своём ПК; код пишет
  ИИ-агент (Arena) в отдельной среде
- **Ничего не выкладывается на GitHub без явного «да»** от разработчика
- Перед релизом — тесты (py_compile + unit-тесты логики)
- Структура веток: `vN.x-release` — замороженные линии,
  `v1.5-gov-release` — GOV-сборка, `arena/…` — рабочая ветка
- Теги: v1.4.2, v1.4.6
- Релиз = коммит + CHANGELOG + номер версии + (по согласованию) push
- Канал: после каждого крупного релиза — пост в стиле v1.3
  (без эмодзи, «Следующий этап: …»)

## 10. Известные странности и долги

1. **Команды «выключись»/«shutdown»** — упомянуты в описании
   релиза v1.5.7, но в чат-команды не добавлены (кнопка ВЫКЛ работает).
   Долг: 2 строки.
2. **STT ходит в Google** (облако) — против философии «данные не
   покидают машину». Замена на локальный Silero STT — в v1.6.2.
3. **3B модель** слабо следует агрессивному prompt'у — ограничение
   железа, не баг. На 7B (ПК) характер в норме.
4. **Канальный пост v1.3** обещал «v1.4 — улучшение гибридного ИИ»,
   а hybrid уехал в v1.6. Закрывается словом «гибридный ИИ» в посте
   о v1.6.
5. На ноуте терминал без DNS (браузер работает) — чинится
   `/etc/resolv.conf`, пока ставится вручную через браузер.
