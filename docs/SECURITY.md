# F.E.D.O. — Анализ безопасности и выбор схем сертификации

Документ для колледжа/защиты: рассматривает F.E.D.O. как продукт
и отвечает на вопрос «какую схему сертификации выбрать».

---

## 1. Описание продукта

**F.E.D.O.** — локальный ИИ-ассистент для персонального компьютера
(GUI + консольный режим, голос, память, много-чат, мониторинг системы).

- **Назначение:** помощь пользователю — диалог, ответы на вопросы,
  работа с кодом, состояние компьютера, голосовое общение.
- **Для кого:** частный пользователь (персональный ПК), перспективно —
  учебные и коммерческие организации, которые хотят локальный ИИ
  «у себя на железе».
- **Функции, связанные с безопасностью:**
  - **Локальная LLM** (LM Studio) — запросы и ответы НЕ покидают
    машину пользователя (в отличие от облачных ИИ);
  - данные пользователя (профиль, чаты, память) хранятся локально
    в `data/` в виде текстовых файлов;
  - журнал операций `data/logs/`;
  - защита функции «Агрессивный режим» подтверждением 18+;
  - блокировка опасных команд в Developer Terminal
    (`rm -rf /`, `mkfs`, `reboot`, `del /f` и т.д.);
  - доступ к LLM только через локальный сервер (localhost).
- **Криптография:** на данный момент не используется
  (направление развития — шифрование хранилища `data/`).

## 2. Целевые рынки

| Рынок | Заказчик | Требования к сертификации |
|-------|----------|---------------------------|
| Частные пользователи (база) | физлица | Нет обязательных |
| Учебные заведения / малый бизнес (рост) | колледжи, IT-компании | 152-ФЗ (персональные данные), ISO/IEC 27001 у партнёров |
| Госсектор (перспектива) | госучреждения | ФСТЭК (Приказ №21), требования к локализации |

## 3. Необходимые схемы

- **Частный рынок:** обязательная сертификация продукта **не требуется**.
  Желательна: внутренняя политика ИБ + «декларация соответствия»
  (лёгкий формат подтверждения).
- **Госсектор (РФ): ФСТЭК России, Приказ №21** — если F.E.D.O.
  разворачивается как СЗИ/ПО, работающее с персональными данными
  в госсистемах. Класс защиты определяется моделью угроз
  (для системы такого профиля типично 1С–2С).
- **Если добавить шифрование данных (v2.0): ФСБ России** —
  сертификация СКЗИ, но только для криптомодуля.
  Практический путь — не изобретать свою криптографию,
  а интегрировать сертифицированный провайдер
  (например, «Крипто ПРО CSP»), как это делают другие продукты.
- **Международный (ЕС/США): Common Criteria / FIPS 140-2** —
  не на старте. CC для небольшой системы реалистично от EAL2+
  (EAL4 — уровень Astra Linux/Windows, это годы и сотни тысяч).
  FIPS — только при выходе на рынок США.
- **Для разработчика (в любой момент): ISO/IEC 27001** —
  это не сертификация продукта, а сертификат системы менеджмента
  ИБ компании-разработчика; для стартапа/команды — «дорого и не срочно»,
  но сильный аргумент в переговорах с B2B-заказчиками.

## 4. Обоснование выбора

Главное собственное свойство F.E.D.O. — **данные не покидают машину**:
локальная нейросеть, локальное хранилище, локальный сервер.
Это напрямую отвечает требованиям:

- **152-ФЗ** (локализация и защита персональных данных):
  данные физически не передаются третьим лицам и не покидают
  юрисдикцию — по архитектуре;
- **ФСТЭК (изоляция персональных данных)**:
  модель угроз упрощается — нет канала утечки через облако;
- **GDPR/CC (ЕС)**: «on-premise» архитектура — аргумент
  для заказчиков, которые не могут отправлять данные в облако.

Поэтому стратегия: **сначала — рынок, где обязателен только 152-ФЗ
(частник + бизнес), ФСТЭК — когда появится конкретный госзаказ,
CC — как «международный допуск» на позднем этапе.**

## 5. Сложности и риски

| Риск | Оценка | Митигация |
|------|--------|-----------|
| ФСТЭК: 4–6 месяцев, стоимость от сотен тыс. ₽, нужен аккредитованный орган | Высокая | Не начинать «на всякий случай» — только под конкретный госконтракт; до этого — декларация соответствия |
| Common Criteria: от ~30–100 тыс. €, 1–2 года | Очень высокая | Отложить; на этапе продукта делать собственный анализ угроз и публичный security-аудит (дешевле и быстрее) |
| Нет собственной криптографии, а «нужно шифрование» | Средняя | Интегрировать сертифицированное СКЗИ (Крипто ПРО CSP) вместо своей крипто — быстрее и легально |
| Текстовые файлы в `data/` (чаты, профиль) — плоское хранение | Средняя (реальный технический долг) | v2.0: шифрование хранилища, права доступа, резервные копии |
| Локальный сервер LM Studio (OpenAI API) без авторизации | Средняя | Привязка строго к localhost (сейчас так и есть) + опциональный локальный ключ доступа |

**Вывод для колледжа:** F.E.D.O. на текущем этапе — продукт
частного/университетского профиля, обязательная сертификация
не требуется; ключевая security-фича (локальность данных)
обосновывает выбор схемы ФСТЭК как целевой для госсектора
и декларации соответствия как ближайшего шага.
